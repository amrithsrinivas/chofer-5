SERVICE SUMMARY
PMData provides historical download access for Polymarket-related datasets and Chainlink stream history.
The public API is download-oriented.
Publicly documented transport formats are:
- Parquet files
- ZIP archives

BASE URL
https://api.pmdata.dev

AUTHENTICATION
type: api_key
documented_header_name: api_key
obtain_key_from: PMData dashboard
documented_examples:
- pandas.read_parquet(..., storage_options={"api_key": "<YOUR_API_KEY>", "User-Agent": "Mozilla/5.0"})
- requests.get(..., headers={"api_key": api_key})
notes:
- User-Agent appears in pandas examples, but the public docs do not explicitly say it is required.
- No Bearer token, OAuth flow, or alternate auth header is publicly documented for the download API.

endpoint:
  id: polymarket_day_archive
  method: GET
  path: /polymarket/{series}/{data_type}/{file_name}
  full_url_template: https://api.pmdata.dev/polymarket/{series}/{data_type}/{series}_{data_type}_{date}.zip
  intent:
    - download a daily PMData archive
    - batch download one Polymarket series and one data type for one day
  path_params:
    - name: series
      type: string
      required: true
      description: market series, shown by examples such as btc-5m, btc-15m, btc-1h, eth-5m
      enum: UNSPECIFIED_IN_PUBLIC_DOCS
      notes:
        - PMData states coverage for 7 up/down coins across 5m, 15m, and 1h
        - the public docs do not provide a clean machine-readable enum list
    - name: data_type
      type: string
      required: true
      enum:
        - poly_l2
        - poly_trade
        - onchain_fills
    - name: file_name
      type: string
      required: true
      pattern: "{series}_{data_type}_{YYYY-MM-DD}.zip"
      description: filename convention shown in docs
  query_params: []
  body: null
  request_schema_json: null
  auth:
    required: true
    header: api_key
  response:
    literal_http_body:
      type: binary
      format: zip
    archive_contents:
      documented_shape: daily archive for one market series and data type
      internal_zip_member_list: UNSPECIFIED_IN_PUBLIC_DOCS
  usage_accounting:
    counted_by: unlocked_day
    semantics:
      - once a day is unlocked, repeated downloads for that same day count once
      - same-day downloads across different data_type values count once
      - same-day downloads across different series values count once
  examples:
    request_url:
      - https://api.pmdata.dev/polymarket/btc-5m/poly_l2/btc-5m_poly_l2_2026-07-18.zip
      - https://api.pmdata.dev/polymarket/btc-5m/poly_trade/btc-5m_poly_trade_2026-07-18.zip
      - https://api.pmdata.dev/polymarket/btc-5m/onchain_fills/btc-5m_onchain_fills_2026-07-18.zip
    normalized_decoded_response_example:
      note: no literal JSON response is documented; response is a ZIP archive

DECODED SCHEMAS

schema:
  id: poly_l2_row
  type: object
  required:
    - market_slug
    - timestamp
    - local_timestamp
    - event_type
  properties:
    market_slug:
      type: string
      description: Polymarket market slug
    timestamp:
      type: timestamp
      description: exchange event timestamp in UTC
    local_timestamp:
      type: timestamp
      description: PMData receive timestamp in UTC
    event_type:
      type: string
      enum:
        - book
        - price_change
        - market_resolved
        - tick_size_change
    ask_prices:
      type:
        - array[number]
        - null
      description: ask price levels for book rows; index 0 is best ask
    ask_sizes:
      type:
        - array[number]
        - null
      description: ask size at each ask price
    bid_prices:
      type:
        - array[number]
        - null
      description: bid price levels for book rows; index 0 is best bid
    bid_sizes:
      type:
        - array[number]
        - null
      description: bid size at each bid price
    best_ask:
      type:
        - number
        - null
      description: best ask after a price change
    best_bid:
      type:
        - number
        - null
      description: best bid after a price change
    pc_price:
      type:
        - number
        - null
      description: changed price level
    pc_size:
      type:
        - number
        - null
      description: new aggregate size at updated price level
    pc_side:
      type:
        - string
        - null
      description: side of updated price level, BUY or SELL
    new_tick_size:
      type:
        - number
        - null
      description: new minimum tick size when announced by the feed
    winning_outcome:
      type:
        - string
        - null
      description: winning outcome when announced by the feed

schema:
  id: poly_trade_row
  type: object
  required:
    - market_slug
    - timestamp
    - local_timestamp
    - event_type
    - outcome
    - price
    - size
    - side
  properties:
    market_slug:
      type: string
    timestamp:
      type: timestamp
    local_timestamp:
      type: timestamp
    event_type:
      type: string
      description: usually last_trade_price
    outcome:
      type: string
      description: usually Yes or No
    price:
      type: number
    size:
      type: number
    side:
      type: string
      description: aggressor side, BUY or SELL

schema:
  id: onchain_fill_row
  type: object
  required:
    - timestamp
    - maker
    - taker
    - outcome
    - maker_side
    - taker_side
    - price
    - usd_amount
    - token_amount
    - transactionHash
  properties:
    timestamp:
      type: timestamp
      description: on-chain transaction timestamp
    maker:
      type: string
      description: maker wallet address
    taker:
      type: string
      description: taker wallet address
    outcome:
      type: string
      description: usually Yes or No
    maker_side:
      type: string
      description: BUY or SELL
    taker_side:
      type: string
      description: BUY or SELL
    price:
      type: number
    usd_amount:
      type: number
    token_amount:
      type: number
    transactionHash:
      type: string

schema:
  id: stream_row
  type: object
  required:
    - symbol
    - observationsTimestamp
    - receiveMicrosecondTimestamp
    - price
    - bid
    - ask
    - version
  properties:
    symbol:
      type: string
      description: feed symbol such as BTCUSD
    observationsTimestamp:
      type: integer
      description: source observation timestamp in seconds
    receiveMicrosecondTimestamp:
      type: integer
      description: receive timestamp in microseconds
    price:
      type: number
      description: reported mid or benchmark price
    bid:
      type: number
    ask:
      type: number
    version:
      type: string

BEST-PRACTICE NOTES FOR AI AGENTS

best_practices:
  - Treat this as a binary-download API, not a JSON CRUD API.
  - Convert Parquet rows to normalized JSON only after download and decode.
  - Always send the api_key header; also send a User-Agent until proven unnecessary.
  - Use date-aware schema handling because PMData publishes changes through product updates rather than URL versioning.
  - Prefer slug_download when you know the exact market slug and need one market.
  - Prefer day archives when you need many markets for the same series/data_type/day.
  - Do not assume Day API archive internals beyond what the docs state.
  - Do not rely on undocumented /examples routes in production systems.
  - Back off and retry conservatively because exact throttle/error semantics are not publicly documented.
  - Protect API keys and avoid logging them.
  - Respect plan/license restrictions and anti-redistribution terms.
